# HookRelay

**Сервис надёжной доставки вебхуков**

HookRelay — backend-сервис на Go для асинхронной доставки вебхуков между независимыми системами.

Проект решает задачу централизованного приёма событий, маршрутизации по подпискам и управления доставками. Основной акцент — надёжность обработки, сохранность данных и независимость приёма событий от их фактической отправки получателям.

> 🚧 **Статус проекта: в разработке**
>
> Реализованы HTTP API для управления endpoints и подписками, приёма событий и создания задач доставки. Сейчас ведётся разработка механизма асинхронной обработки и отправки вебхуков.

## Архитектура

HookRelay построен как модульный монолит с двумя режимами запуска: API и Worker.

```text
Внешние системы
       |
       v
    HTTP API
       |
       v
   PostgreSQL
   ├── Endpoints
   ├── Subscriptions
   ├── Events
   └── Deliveries
       |
       v
     Worker
       |
       v
  HTTP Endpoints
  получателей
```

PostgreSQL используется как постоянное хранилище данных и очередь задач доставки. API принимает события и создаёт связанные задачи, а Worker независимо обрабатывает их.

## Реализованная функциональность

- Регистрация и получение списка endpoints.
- Управление подписками на типы событий.
- REST API для приёма событий.
- Маршрутизация событий по подпискам.
- Атомарное сохранение событий и задач доставки с использованием транзакций PostgreSQL.
- Хранение статусов и данных для планирования доставок.

## Технологии

| Технология | Назначение |
|---|---|
| Go | Backend-разработка |
| PostgreSQL | Хранение данных и очередь доставок |
| pgx | Взаимодействие с PostgreSQL |
| REST API / HTTP | Приём событий и API |
| SQL Migrations | Управление схемой БД |

## Ключевые инженерные решения

- Асинхронная обработка задач.
- Транзакционная целостность данных.
- Конкурентная обработка доставок через PostgreSQL.
- Модель доставки at-least-once.
- Автоматические повторы и обработка окончательных ошибок.
- HMAC-SHA256 для проверки подлинности вебхуков.
- Корректное завершение приложения и освобождение ресурсов.

## Перспективы развития

Проект развивается в сторону полноценной системы надёжной доставки вебхуков. В дальнейшем планируется реализация конкурентных Worker, подписания запросов HMAC-SHA256, автоматических повторов с экспоненциальной задержкой, обработки окончательно неудачных доставок и отслеживания истории попыток.

Также планируется добавить Docker Compose, интеграционные тесты, мониторинг через Prometheus и Grafana.
